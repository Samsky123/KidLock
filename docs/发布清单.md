# 公开发布清单

把本仓库发布到 GitHub / Gitee 时按此顺序操作。假设仓库名为 `KidLock`。

## 1. 发布前自检

- [ ] `./gradlew assembleDebug` 通过
- [ ] `git status` 中没有 `*.jks`、`keystore.properties`、`local.properties`
- [ ] 仓库内没有 APK（APK 通过 Releases 分发，`.gitignore` 已排除）
- [ ] README 中的截图、教程、许可链接均可打开
- [ ] `CHANGELOG.md` 版本号与 `app/build.gradle` 一致
- [ ] 在干净目录 `git clone` 后能按 README 构建成功
- [ ] **备份 release 签名密钥**：默认在 `~/.kidlock-signing/`（密钥库 + 口令文件）。
      丢失后无法对已安装用户发布覆盖升级，必须妥善离线备份。

> 当前 App 已从上级项目仓库拆分为独立仓库（`android-kidlock/.git`），
> 上级仓库只保留内部文档与历史备份，**不要**把整个项目目录当作公开仓库推送。

## 2. 创建远程仓库

**GitHub（推荐，使用 gh CLI）**

```bash
gh auth login                       # 先完成浏览器授权
gh repo create <你的账号>/KidLock --public --source=. --remote=github \
  --description "Android 儿童手机管控：答题解锁 + 按 App 限时，纯本地、无网络权限"
git push -u github dev
```

**Gitee（国内访问更快）**

```bash
git remote add gitee git@gitee.com:<你的账号>/KidLock.git
git push -u gitee dev
```

## 3. 仓库设置

- Description：`把玩手机的时间变成答对题才给 · Android 原生 · 无网络权限`
- Topics：`android` `kotlin` `parental-controls` `screen-time` `kids` `offline` `privacy`
- 开启 Issues；Discussions 可选；Wiki 不需要
- About 里勾选 Releases、Packages 按需
- 若双远程，建议 `main` 为稳定分支、`dev` 为开发分支

## 4. 发布第一个 Release

```bash
# 从 dev 合并到 main 后打标签
git checkout main
git merge --no-ff dev
git tag -a v1.4.1 -m "v1.4.1 开源版：安全加固"
git push github main --tags
git push gitee main --tags
```

在 Releases 页面新建 `v1.4.1`：

- 标题：`v1.4.1 · 首个开源版本`
- 说明：直接取 `CHANGELOG.md` 的 1.4.1 段落
- 附件：上传 `KidLock-v1.4.1.apk`（由 `app/build/outputs/apk/debug/app-debug.apk` 改名）
- 勾选 `Set as the latest release`

> 公开分发的 APK 建议使用自己的 release 密钥签名（见 README「打 release 包」），
> 不要长期用 debug 签名，否则后续换签名会导致无法覆盖升级。

## 5. 发布后检查

- [ ] 未登录浏览器打开仓库，README 图片能正常显示
- [ ] Releases 里的 APK 能下载，`sha256sum` 与本地一致
- [ ] 手机侧载安装、首次创建账号、答题解锁全流程通过
- [ ] 从 Release 下载的 APK 与源码构建的版本号一致
- [ ] 没有把 internal 文档、测试截图、本机路径带进公开仓库

## 6. 后续维护

- 每次发版更新 `CHANGELOG.md` 与 `versionCode` / `versionName`
- 安全修复按 `SECURITY.md` 流程处理
- 教材换版只需改 `tools/build_catalog.py` 的 `MAPPING` 并重新生成
